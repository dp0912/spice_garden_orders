
# 🍽️ Spice Garden — Food Ordering & Daily Budget Planner

**A Flutter and Dart mobile application powered by SQLite.**

Spice Garden is a restaurant-themed food ordering and daily budget planning application. Users can browse an Indian restaurant menu, manage food items, create order plans for selected dates, enforce daily spending limits, and manage previously saved orders.

The application uses a local SQLite database for persistent storage and does not require an internet connection to manage menu items or order plans.

## Overview

Spice Garden combines restaurant menu management with a daily food budgeting system.

Rather than allowing users to select food without considering cost, the app helps them plan their meals within a user-defined daily spending limit.

Users can select a date, specify a budget in Canadian dollars, choose food items, and save a complete order plan to SQLite. Saved plans can later be retrieved, edited, or deleted.

### Main Features

- Restaurant-themed home screen with custom burgundy and cream colours
- SQLite database seeded with 20 Indian food items on first installation
- Food menu displaying names, categories, and prices in CAD
- Add, edit, and delete food items
- Daily budget input with monetary validation
- Calendar date picker for creating order plans
- Multiple food selection with real-time cost calculations
- Prevention of selections that exceed the daily budget
- Persistent storage of order plans in SQLite
- Date-based search for previously saved orders
- Order history sorted by date, newest first
- Detailed saved-order view with itemized prices
- Update existing orders, including date, budget, and foods
- Delete saved orders with confirmation
- Local data persistence across application restarts
- Automated Dart unit tests and a Flutter widget test

## Application Screens

### 1. Home Screen

The Home screen introduces the Spice Garden restaurant application and provides navigation to the three primary sections:

- **View Menu:** Browse and manage available food items.
- **Plan Daily Order:** Create a new date-specific order plan.
- **Order History:** Search, inspect, update, or delete saved orders.

The application's visual theme uses burgundy (`#7A2329`) and cream (`#FFF4E5`) with Material Design widgets, customized buttons, icons, and cards.

### 2. Restaurant Menu

The menu is loaded from the SQLite `food_items` table.

Each food entry displays:

- Food name
- Food category
- Price in Canadian dollars
- Edit action
- Delete action

The Add Food button opens a form for entering a new food item.

Input validation prevents empty food names, missing categories, invalid prices, and non-positive prices.

Deleting an item requires confirmation before the corresponding database record is removed.

The menu refreshes after successful database modifications.

### 3. Daily Order Planner

The Daily Order Planner allows users to:

1. Enter a positive daily budget in CAD.
2. Select an order date using a date picker.
3. Browse available food items.
4. Select or deselect foods using checkboxes.
5. View the current total and remaining budget.
6. Save the completed order plan.

The application calculates the selected total as users make changes.

If selecting another food would exceed the budget, the app rejects that selection and displays a warning.

The Save Order Plan action validates the inputs and stores the plan in SQLite.

### 4. Order History and Date Search

The Order History screen displays all saved order plans, sorted by date in descending order.

Users can select a date and query SQLite for the matching order.

When an order exists, the application displays its date, daily target, and total cost.

When no matching order exists, a not-found message is displayed.

Selecting an order opens its details, including an itemized list of the foods saved with that plan.

### 5. Edit Order Plan

The Edit Order Plan screen loads an existing order and allows users to change:

- Daily budget
- Order date
- Selected food items

The screen recalculates the total and remaining budget as the selection changes.

An update is rejected when the order exceeds the budget or when its date conflicts with another saved order.

Successful updates are written to SQLite within a transaction.

## SQLite Database Design

The application stores its data in a local SQLite database named:

`spice_garden.db`

Database initialization and schema creation are implemented in:

`lib/data/restaurant_database.dart`

The database contains three main relational tables.

### Table 1 — food_items

Stores available restaurant menu items.

| Column | Type | Description |
|---|---|---|
| id | INTEGER | Primary key |
| name | TEXT | Food item name |
| category | TEXT | Food category |
| price_cents | INTEGER | Price stored in cents |

The database enforces a positive price using a CHECK constraint.

### Table 2 — order_plans

Stores each saved daily order plan.

| Column | Type | Description |
|---|---|---|
| id | INTEGER | Primary key |
| plan_date | TEXT | Order date (YYYY-MM-DD) |
| target_cents | INTEGER | Daily budget |
| total_cents | INTEGER | Total order cost |

The `plan_date` column has a UNIQUE constraint, allowing one saved order plan per date.

### Table 3 — order_plan_items

Stores the selected foods associated with each order.

| Column | Type | Description |
|---|---|---|
| id | INTEGER | Primary key |
| plan_id | INTEGER | References an order plan |
| food_id | INTEGER | References a menu item; nullable |
| item_name | TEXT | Saved food name |
| price_cents | INTEGER | Saved food price |

This table links each order plan to its selected foods.

The food name and price are also stored as snapshots, preserving the saved order details even if an original menu item is later modified.

### Database Relationships

- One order plan can contain multiple selected food items.
- Each saved order item belongs to one order plan.
- Deleting an order plan automatically deletes its associated order items through `ON DELETE CASCADE`.
- Deleting a food from the menu sets its reference in saved orders to NULL through `ON DELETE SET NULL`.

Foreign-key enforcement is enabled when SQLite opens.

### Transactions

Database transactions are used for saving and updating complete order plans.

For example, saving an order involves inserting the order header into `order_plans` and inserting each selected food into `order_plan_items`.

These operations are performed as a single transaction so that a failed operation does not leave a partially saved order.

## Daily Budget Validation

All monetary calculations use integer cents rather than floating-point currency values.

For example:

- $30.00 becomes 3000 cents.
- $18.99 becomes 1899 cents.
- $4.99 becomes 499 cents.

This avoids common floating-point rounding problems when working with currency.

### Example Order

| Item | Cost |
|---|---:|
| Butter Chicken | $18.99 |
| Jeera Rice | $4.99 |
| **Selected Total** | **$23.98** |
| Daily Target | $30.00 |
| **Remaining Budget** | **$6.02** |

The user can save this order because the total is within the daily target.

If the user attempts to add Veg Pakora ($6.50), the new total would be $30.48.

Since $30.48 exceeds the $30.00 daily target, the selection is rejected.

The budget system also validates:

- Empty and invalid budget inputs
- Negative or zero budgets
- Amounts with more than two decimal places
- Orders without selected food items
- Orders exceeding the target after the budget is changed
- Duplicate dates when saving or updating orders

An order costing exactly the daily target is allowed.

Budget parsing and calculation helpers are located in:

`lib/utils/budget_utils.dart`

## CRUD Operations

The application supports Create, Read, Update, and Delete operations for both food items and order plans.

| Operation | Food Items | Order Plans |
|---|---|---|
| Create | Add Food form | Save Order Plan |
| Read | View Menu | Order History and date search |
| Update | Edit Food form | Edit Order Plan |
| Delete | Delete Food confirmation | Delete Order Plan confirmation |

### Food Management

`lib/data/food_repository.dart`

Provides methods for inserting, updating, and deleting menu items.

### Order Creation

`lib/data/restaurant_database.dart`

Creates complete saved orders using SQLite transactions.

### Order Queries

`lib/data/order_history_repository.dart`

Retrieves saved plans, searches by date, and loads their itemized contents.

Order history uses:

`ORDER BY plan_date DESC, id DESC`

to display the newest saved plans first.

### Order Updates and Deletion

`lib/data/order_plan_crud_repository.dart`

Updates existing plans and deletes saved orders.

When updating a plan, current menu prices are read from SQLite and the order total is recalculated before the transaction is committed.

The update operation replaces the previously selected foods with the new selection.

Deleting an order plan uses the database's cascading foreign-key relationship to remove the associated order items.

## Installation and Setup

### Prerequisites

Before running the project, install:

- Flutter SDK with a compatible Dart SDK
- Android Studio
- Flutter and Dart plugins for Android Studio
- Android SDK and an Android emulator
- Git

The project specifies Dart SDK compatibility in `pubspec.yaml` using:

`^3.14.0`

### Step 1 — Clone the Repository

```bash
git clone https://github.com/dp0912/spice_garden_orders.git
```

### Step 2 — Enter the Project Directory

```bash
cd spice_garden_orders
```

### Step 3 — Install Dependencies

```bash
flutter pub get
```

### Step 4 — Verify Flutter Setup

```bash
flutter doctor
```

Resolve any Android development setup issues reported by Flutter.

### Step 5 — Start the Emulator

Open Android Studio and launch an Android virtual device using Device Manager.

Check the available devices:

```bash
flutter devices
```

### Step 6 — Run the Application

```bash
flutter run
```

If multiple devices are available, specify the appropriate Android device ID.

For example, when the emulator is listed as `emulator-5554`:

```bash
flutter run -d emulator-5554
```

The application initializes SQLite automatically and seeds the menu on first database creation.

No separate database server, cloud account, API key, or manual SQL setup is required.

## How to Use the Application

### Browse and Manage the Menu

1. Launch Spice Garden.
2. Select **View Menu**.
3. Browse food items and their prices.
4. Press **Add Food** to create a new menu item.
5. Use the pencil icon to edit an existing food item.
6. Use the trash icon to delete an item after confirmation.

### Create a Daily Order Plan

1. Return to the Home screen.
2. Select **Plan Daily Order**.
3. Enter a daily target amount.
4. Select the desired date.

6. Review the selected total and remaining budget.
7. Press **Save Order Plan**.

1. Open **Order History**.

1. Open **Order History**.
2. Locate the order to modify.
3. Press the pencil icon.

5. Review the recalculated order total.
6. Press **Update Order Plan**.

1. Open **Order History**.
2. Locate the order.
3. Press the trash icon.
4. Review the confirmation dialog.

## Design and Implementation Decisions

### Local-First Database

SQLite was selected because the assignment focuses on local persistent storage and does not require a remote backend.

This also allows the application to manage saved data without internet connectivity.

### Integer Currency Storage

Prices and budgets are represented as integer cents to make money calculations predictable and avoid floating-point precision errors.

### Relational Data Model

Separating food items, order plans, and selected order items supports structured database queries and referential integrity.

### Saved Order Snapshots

The application stores each selected food's name and price with the saved order.

This allows previously saved order details to remain available when menu entries are changed or deleted.

### Database Transactions

Transactions are used when writing related order records to protect against partial updates.

### Input Validation

Both the interface and database operations validate important values, including budgets, selected items, duplicate dates, and food prices.

### Modular Code Structure

The application separates UI screens, model classes, database operations, and reusable utility functions to improve readability and maintainability.

## Current Scope and Limitations

Spice Garden is an academic food ordering and budget planning prototype.

- Food prices are illustrative rather than live restaurant prices.
- Orders are stored locally on the device.
- One saved order plan is permitted per date.
- No user authentication or cloud synchronization is implemented.
- The application does not process payments or send orders to a real restaurant.
- Database schema version 1 does not yet include migration logic for future schema changes.
- The application has been tested primarily using an Android emulator.
- The current automated tests focus on budget logic and Home screen rendering rather than full database integration testing.

These limitations are outside the core scope of Assignment 3.
